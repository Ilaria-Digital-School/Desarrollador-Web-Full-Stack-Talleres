# Preparar su puesto de trabajo completo, versionarlo y documentarlo

Recordatorio: terminal, Git y versiones Un terminal es una ventana donde usted da órdenes escritas al sistema. El terminal integrado del editor es esa misma ventana, abierta dentro de su editor de código, lo que le evita cambiar de aplicación. Un repositorio Git es una carpeta cuyo historial queda registrado en una subcarpeta oculta llamada .git. Retenga este modelo mental de tres zonas. El directorio de trabajo contiene sus archivos tal como los ve. El área de preparación recibe lo que usted selecciona con git add. El repositorio conserva las versiones que usted confirma con git commit. Un commit es una fotografía de los archivos preparados, acompañada de un autor, una fecha y un mensaje. El comando git log muestra la lista de esas fotografías. El comando git status le indica en todo momento en qué zona se encuentra cada archivo. Hay tres errores frecuentes. El primero es olvidar git add y creer que un archivo modificado ya está guardado. El segundo es escribir mensajes vagos como «cambios» o «arreglo». El tercero es confirmar sin haber configurado su identidad, de modo que los commits llevan un nombre incorrecto. Un miniejemplo: usted modifica 3 archivos y ejecuta git add sobre 2 de ellos. Tras git commit, el historial gana 1 commit que contiene esos 2 archivos. El tercero sigue apareciendo como modificado en git status, porque nunca pasó por el área de preparación.
