# Escribir el Product Backlog del proyecto en user stories

Recordatorio teórico El Product Backlog es la lista ordenada de todo lo que el producto debe ofrecer. Lo gestiona el Product Owner, que decide el orden de prioridad. Cada elemento se redacta casi siempre como una user story: una frase corta que describe una necesidad desde el punto de vista de quien la utiliza. El formato estándar es «Como [rol], quiero [acción], para [beneficio]». El rol indica quién tiene la necesidad, la acción indica qué quiere hacer y el beneficio explica por qué es valioso. Una story se completa con criterios de aceptación: condiciones verificables que permiten decir sin ambigüedad si la funcionalidad está terminada. Por último, el equipo estima el esfuerzo con una escala relativa, por ejemplo la de tallas de camiseta: XS, S, M, L, XL. Como modelo mental, piense en la story como una promesa de conversación: describe el qué y el porqué, nunca el cómo técnico. Los errores frecuentes son escribir una tarea técnica («crear la tabla productos»), olvidar el beneficio, usar un rol vago como «el usuario» o redactar criterios imposibles de comprobar («la página debe ser bonita»). Mini-ejemplo: «Como cliente, quiero filtrar los productos por categoría, para encontrar rápidamente lo que busco». Criterios: al elegir «Camisetas», solo se muestran camisetas; si una categoría está vacía, aparece el mensaje «Ningún producto disponible». Estimación: S.
