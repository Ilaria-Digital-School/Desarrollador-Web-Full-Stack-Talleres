# Un problema de orden de archivos resuelto, de la descomposición al terminal

Recordatorio: descomponer antes de teclear Descomponer un problema es dividirlo en acciones pequeñas, ordenadas y verificables antes de ejecutar nada. En el terminal, cada acción se traduce en una o varias órdenes. Las básicas son pwd para saber dónde está, ls para ver el contenido, cd para cambiar de carpeta, mkdir para crear una carpeta, touch para crear un archivo vacío y mv para mover o renombrar. El modelo mental útil es este: primero el plan escrito, después la orden, después la verificación con ls o git status y, por último, el commit. Git es su red de seguridad. Cada commit es una foto del proyecto a la que puede volver si algo sale mal. Los errores más frecuentes son tres. El primero es estar en la carpeta equivocada sin haberlo comprobado con pwd. El segundo es olvidar las comillas en un nombre con espacio, lo que hace que el terminal lo interprete como dos archivos distintos. El tercero es usar un motivo genérico como *.pdf sin comprobar antes qué archivos atrapa. Un miniejemplo con cifras: imagine una carpeta con 20 archivos, de los cuales 9 terminan en .pdf, es decir, 4 facturas, 1 copia de factura y 4 contratos. Si teclea mv *.pdf facturas/ pensando en las facturas, moverá 9 archivos en lugar de 4. Si antes lanza ls *.pdf, ve los 9 nombres y corrige su motivo, por ejemplo con factura_2024_0*.pdf. Esa simple verificación previa es exactamente el reflejo de depuración que usted ha practicado: reproducir, aislar, corregir,...
